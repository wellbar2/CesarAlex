# Validation and quality assurance

## Automated checks

Install the development dependencies and run:

```bash
python -m pip install -e ".[dev]"
python -m ruff format --check cesaralex tests examples app.py
python -m ruff check cesaralex tests examples app.py
python -m pytest
python -m pytest --cov=cesaralex
python -m build
```

Continuous integration repeats linting and the test suite on Python 3.10, 3.11,
and 3.12. A separate workflow compiles the JOSS paper.

## What the tests verify

| Area | Objective |
| --- | --- |
| Lattes parsing | Name, ORCID, title, year, and DOI extraction from synthetic HTML |
| Normalization | Common DOI prefixes, case, missing values, ORCID, and OpenAlex IDs |
| Matching | Conservative name-overlap behavior and report fields |
| Source integration | ORCID/OpenAlex/Lattes union and presence flags |
| No-ORCID path | Empty curricula remain in reports and DOI fallback works |
| Inferred profiles | A cached hit marks OpenAlex presence, preserves the true ID/name, and avoids a second DOI request |
| HTTP accounting | List, singleton, balance, retry, and reported-cost counters |
| Balances | Daily/prepaid parsing, aggregation across keys, and intermediate estimates |
| Reporting | Stable CSV encoding, delimiters, quoting, warning tables, and coverage counts |
| Interface smoke test | Streamlit starts without exception and renders the principal controls and three sidebar bars |

All automated API responses are simulated. Tests therefore remain deterministic,
do not spend an OpenAlex balance, and do not depend on the availability of an
external service.

## Manual release check

Before tagging a release, a maintainer should also:

1. create a clean virtual environment and install with `pip install -e .`;
2. run the complete automated checks;
3. start `streamlit run app.py`;
4. confirm balance refresh with a valid test key;
5. process a synthetic or authorized Lattes HTML with and without ORCID;
6. repeat with DOI checking enabled and disabled;
7. open the individual and consolidated CSV outputs;
8. verify the Sankey and coverage diagram;
9. confirm that no API key appears in output or logs intentionally generated by
   the application;
10. build the source and wheel distributions.

Record the operating system, Python version, application version, test result,
and date in the release notes.

## Research validation

The workflow from which CesarAlex evolved supported a published coverage study
of 16,203 Lattes curricula and approximately 1.1 million
researcher-publication records. The current repository adds modularity,
regression tests, request-saving inferred-profile behavior, and usage monitoring
to that research workflow. The associated publication and open result dataset
are cited in `paper/paper.bib`.

Automated tests validate software rules; they do not establish that external
metadata are complete or error-free. Source coverage and inferred author matches
must be interpreted as research observations with the limitations documented in
the README.
